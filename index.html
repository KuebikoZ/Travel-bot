01

为谁、在什么时候解决什么

先切一个小口子：不做灵感期种草，也不做行中导航，只做「行前方案」这一段。

谁

行前方案的决策人

自由行规划期的个人、情侣、家庭决策者，核心是 25–40 岁人群。独行占 42%、家庭游占 27%，80/90 后占 73%（参考马蜂窝 2026 报告）。

什么时候

出行前 1–4 周

目的地基本定了，但「怎么安排才顺、预算够不够」还没答案。此刻他要的不是更多信息，是一份能直接执行的排期。

现在怎么办

三件事拼起来用

刷小红书笔记自己拼、用 OTA 行程助手生成一版、再丢给通用 AI 问一遍——三份都不完整，最后还得自己核对时间。

02

三个卡点，对应三个动作

痛点不是「AI 不会写行程」，而是「写出来的东西不敢用」。

用户卡在哪根因我们做什么
需求说不清 用户本来就说不出完整约束，只丢一句「帮我做个攻略」 结构化澄清：3–5 个问题、点选式、20 秒填完
回答千篇一律 生成端缺少个性化输入，只能给模板 约束化生成：天数、预算、同行人、节奏显式采集后建模
照着走会翻车 AI 隐式猜测 + 数据时效无保障 + 路线本身不成立 约束透明 + 事实可溯 + 时空校验：不暗猜、不编造、不荒谬
03

一条链路走到底：六个阶段

Demo 左侧的进度条就是这六步，可以完整走一遍。

1

意图识别与路由

含出行意图 + 方案生成意图才进垂类，其余转通用搜索，不硬接。

2

需求理解
一页合一

预填与待确认同卡：绿底是猜的（带依据），橙底等你点头，一次确认。

3

多源信息采集

事实找结构化 POI，时效找搜索，口碑找 UGC，各取所长。

4

生成与校验

约束建模 + 地图 API 时空硬校验；不过就自动回改一轮再复检。

5

透明化呈现

前提写清楚、交通衔接可见、依据与核验时间标出来。

6

调整与采纳

改预算、砍天数只做局部重排；采纳行为反哺画像。

第 2 步「一页合一」是整条链路的效率关键：把猜的和要问的放在同一屏，用户只做一次确认。
04

什么才算「可被采纳的方案」

五条同时满足，缺一不合格；前三条是一票否决的红线。

1

硬约束满足红线

用户显式给出的天数、预算档、同行人构成 100% 被遵守，不擅自「优化」。

2

时空合理红线

无回头路、无闭馆日冲突、相邻点通勤时间符合现实——用地图 API 逐段校验。

3

事实真实红线

价格、班次、营业状态标来源与更新时间；查不到的明说「出发前请确认」，绝不编。

4

无需二次加工

按天分块 + 交通衔接 + 预算表，用户核对一遍就能出发。

5

可交互调整

改预算、砍天数局部秒级重排，而不是整份重来。

参照北二外《AI 旅游出行助手能力测评报告（第三期）》：16 款主流产品总分仅 35–61 分，「违背硬约束 / POI 时空不合理 / 逻辑矛盾」计 0 分。
换句话说：做到这五条本身就是差异化——不是卷生成能力，而是卷「敢不敢被拿去用」。
05

怎么衡量它有用

生成出来不算成功，被拿去执行才算。

北极星指标

方案采纳率

生成完整方案后 7 日内 发生 导出 / 收藏 / 分享 / 行中回访 任一行为的会话占比。

驱动

把链路做顺

澄清完成率、单方案调整轮次、关键事实来源覆盖率 —— 三个都直接作用在链路上游。

护栏

别把信任做坏

时空错误抽检通过率、用户纠错率、重复生成率。重复生成高，说明方案不敢用。

优先级

先治最痛的两处

P0 澄清与透明（低成本直接治痛点）→ P1 个性化 → P2 信任飞轮与生态。

06

接什么，不接什么

垂类能力最怕边界模糊：什么都答，就等于什么都不专。

✓范围内

  • 境内自由行的行前方案生成（交通 + 景点 + 住宿）
  • 按用户约束定制，与多轮调整
  • 行程合理性校验与来源标注

—范围外（转通用搜索或明示不支持）

  • 灵感期选目的地（「十一去哪人少」→ 给灵感卡片，不做深方案）
  • 单一事实查询（「故宫门票多少钱」→ 通用搜索）
  • 行中实时需求（排队 / 导航 → 转地图能力）
  • 签证出入境等强时效高风险信息 → 明示以官方为准
另外，前端做了三层兜底：接口 12 秒超时、失败自动重试一次 → 仍不通就切到本地样例数据 → 连本地引擎异常也有一份固定的离线模板。任何一层出问题页面都不会白屏，而且降级时会在对话里明确标注「这不是实时结果」——不拿样例冒充实时，这和「事实真实」那条红线是同一套原则。
07

竞品都占住了什么，空位在哪

三类玩家各有优势，但没人同时做到「中立 + 透明 + 可改」。

OTA 行程助手

有交易闭环，库存真实；但行程偏标准化，个性化弱。

内容平台 AI

灵感与口碑丰富，但行程与真实库存、营业时间脱节。

通用大模型

生成力强、写得好读，但模板化，事实要用户自己核。

出游搭子 → 空位

中立立场 + 约束透明 + 可交互调整，占住「直接可用的个性化方案」。
